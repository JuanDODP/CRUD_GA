1. ¿Qué es la Continuidad Operativa?

Definición, alcance y objetivo del documento

La continuidad operativa es la capacidad del sistema para seguir funcionando correctamente después de que el equipo de desarrollo original entregue el proyecto. No depende únicamente del software en sí, sino de que las personas responsables de operarlo cuenten con la información y los recursos necesarios para hacerlo.

Este documento formaliza el cierre del proyecto CRUDGA identificando cada artefacto producido, su propósito, su destinatario y cómo contribuye a que el sistema pueda instalarse, usarse, mantenerse y evolucionar de forma autónoma.

ℹ️
¿A quién va dirigido este documento?

Al responsable de recibir el sistema — ya sea el cliente, el área de TI, el administrador o el siguiente equipo de desarrollo. Es el punto de entrada que les indica qué tienen en sus manos y cómo empezar.

3. Roles y Responsabilidades Post-Entrega

Quién hace qué a partir de la recepción del sistema

Rol Responsabilidad principal Documento de referencia
Administrador del sistema Gestionar usuarios, áreas, proyectos y asignaciones. Monitorear el uso diario de la plataforma. manualUser.html
Administrador de TI Mantener el servidor Docker activo, realizar backups de la base de datos, gestionar credenciales y accesos. manualInstall.html §4–7
Desarrollador de mantenimiento Aplicar correcciones de bugs, actualizar dependencias, extender funcionalidades del sistema. manualInstall.html §10–14
Usuario final Consultar el sistema, registrar asignaciones, generar reportes y exportar datos según su rol. manualUser.html
⚠️
Punto crítico: credenciales y variables de entorno

El archivo .env del Backend contiene las credenciales de la base de datos y no debe subirse al repositorio Git. El administrador de TI es responsable de custodiarlo, respaldarlo y actualizarlo en caso de cambio de contraseñas o servidores.

4. Protocolo Básico de Contingencia

Qué hacer ante los escenarios de fallo más comunes

El sistema no responde o está caído

  • Verificar que Docker Desktop está corriendo

    El ícono de la ballena en la barra del sistema debe indicar estado activo. Si no, abrirlo y esperar a que inicie.

  • Comprobar el estado del contenedor de base de datos

    En terminal: docker ps. El contenedor CRUDGA_DB debe aparecer como Up. Si no, ejecutar docker compose up -d desde el directorio del Backend.

  • Reiniciar el Backend y el Frontend

    Detener ambos procesos (Ctrl+C en cada terminal) y volver a ejecutarlos siguiendo el orden de arranque del manualInstall.html §7.

  • Revisar logs del contenedor

    Si el problema persiste: docker logs CRUDGA_DB para diagnosticar el motor de base de datos. El manualInstall.html §8 contiene los errores más frecuentes y sus soluciones.

Pérdida o corrupción de datos

  • Detener el contenedor inmediatamente

    Ejecutar docker compose down para evitar que se escriban más datos sobre un estado inconsistente.

  • Restaurar desde el último backup

    Los datos persisten en la carpeta mssql-data/ del servidor. Si se dispone de un backup previo de esta carpeta, restaurarlo antes de volver a levantar el contenedor.

⚠️
El sistema no incluye backups automáticos

La versión entregada no tiene una política de backups programados. Es responsabilidad del administrador de TI implementar una rutina de copia de la carpeta mssql-data/ con la frecuencia que requiera el negocio.
